# Планирование: анализ, идентификация проблем и поиск решений

## Существующие проблемы

 * Низкая производительность MES
   * Долгая загрузка дашборда с заказами
   * Медленный расчёт стоимости заказа по 3D-модели
 * Проблемы с обработкой заказов
   * Потеря заказов при интеграции через API
   * Клиенты не получают заказы вовремя
 * Отсутсвие масштабирования, из-за чего при росте количества заказов возникают ошибки и задержки, которые отпугивают клиентов
 * Долгие релизы из-за ручного E2E тестирования
 * Возможность потери данных из-за отсутствия репликации

## Предлагаемые инициативы в порядке приоритета

 * Выделить часть MES, отвечающую за расчёт стоимости модели, в отдельный микросервис, настроить его масштабирование, судя по всему это узкое место в текущей архитектуре, так один пользователь может занять всю систему на пол часа.
 * Так же для MES реализовать кеширование запросов списка заказов, что бы операторам не приходилось долго ждать.
 * Настроить сбор метрик, трейсов и логов в объёме, необходимом для выявления основных проблем
 * Добавление реплик БД для ускорения READ-запросов и уменьшения вероятности потери данных
 * Добавление кеширования в остальные части системы
 * Реализация балансировки нагрузки в остальные части системы 
 * Внедрение логирования (ELK)
 * Автоматизация E2E тестирования

Выполнение первых трёх задач уже может улучшить общую отзывчивость системы и уменьшить количество жалоб как от B2B, так и от B2C пользователей.

## Целевая система через пол года
 * Внедрён трейсинг, мониторинг и логирование системы с включёнными алертами;
 * Расчётная часть MES вынесена в отдельный сервис
 * Добавлены реплики БД для балансировки нагрузки на чтение и минимизации рисков потери данных; 
 * Реализованно кеширование запросов на получение статусов заказов для повышения отзывчивости веб-приложения MES.
